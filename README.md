# Winner, Winner, Chicken dinner!

<img width="2816" height="1536" alt="chickendinner" src="https://github.com/user-attachments/assets/f9f51da3-efdb-4515-8fbb-e9a8862e1c74" />


This repo is a sample repo where the end goal is to serve
arbitrary "stock exchange" winners from a pre-generated CSV file.
Result will be delivered in a JSON.

This project utilize:

- UV
- FastAPI
  - FastAPI Test Client for endpoint tests
- Pandas for file loading and manipulating data
- Pydantic for validation
- Pytest for testing
- Jupyter notebook for data discovery


- Bonus: raw http client for base lib showoff
- Bonus: raw validation examples for base lib showoff

## Setup

### Prerequisites

- Python >= 3.10
- [uv](https://docs.astral.sh/uv/getting-started/installation/)

### Local development (uv)

Install dependencies:

```bash
uv sync
```

Run the API in development mode (with auto-reload):

```bash
uv run fastapi dev src/chicken_dinner/main.py
```

`main.py` locates `results.csv` at the repo root automatically (resolved
relative to the source file, not the process's working directory). To point
it at a different CSV, set `RESULTS_CSV_PATH`:

```bash
RESULTS_CSV_PATH=/path/to/other.csv uv run fastapi dev src/chicken_dinner/main.py
```

The API is now available at `http://127.0.0.1:8000`, with interactive docs
at `http://127.0.0.1:8000/docs`.

### Testing

The suite in `tests/` is split into two layers:

- `tests/test_datautils.py` — unit tests for the pure data-transformation
  logic in `datautils.py` (`load_csv`, `extract_and_rank_stocks`,
  `pick_winners`). These run against small in-memory DataFrames and CSV
  fixtures under `tests/fixtures/`, independent of the real `results.csv`,
  so they stay meaningful even as the production dataset changes.
- `tests/test_winners.py` — integration tests that exercise the real
  FastAPI app via `TestClient`, hitting `/` and `/results`. Each test points
  the app at a fixture CSV via the `RESULTS_CSV_PATH` env var, covering both
  the happy path and the missing-file error path.

```bash
uv run pytest
```

### Docker

A `Dockerfile` and `docker-compose.yml` are included to run the app without
installing Python or uv locally.

```bash
docker compose up --build
```

The API will be available at `http://localhost:8000`. Stop it with:

```bash
docker compose down
```

## Data discovery

`stocktests.ipynb` is the Jupyter notebook I used to explore `results.csv`
before writing any application code: grouping stocks by day, working out how
to find each stock's closing price per day, and prototyping the growth and
ranking calculations. It's kept in the repo as a record of how the logic in
`datautils.py` evolved, not as something meant to be run as part of the app.

# Important note
While this application mainly use FastAPI for the web layer,
I am providing an example of how to create an endpoint with
a more barebone entrypoint with Python HTTP.

## About AI use
The application code (`src/`) is entirely my own — no AI coding was used to
write it. This project is meant as a showcase of my current Python level and
my understanding of the language. I used Gemini and Google to look up Pandas
documentation and edge cases while figuring out how to extract the winner
data, and there are some traces of autocompletion, but every implementation
choice is mine.

Everything around the application code is a different story: the test suite
(`tests/test_datautils.py`, `tests/test_winners.py`, their fixtures, and the
test strategy described above) and the infrastructure (this README's setup
instructions, `Dockerfile`, and `docker-compose.yml`) were generated by an
LLM (Claude Code) against my existing code, to save time. I reviewed and ran
all of it, but did not hand-write that logic myself.
